                                                       *diffview*
Requires Vim 9.1 with +vim9script, +diff, +windows, +job and +timers,
and Git on PATH. Verified: macOS, Vim 9.1.1950, Git 2.54.0. No earlier
minimum patch level is verified. Neovim/older Vim are unsupported.
Install as a standard Vim plugin/package together with preservim/nerdtree
(formerly scrooloose/nerdtree). Missing or incompatible NERDTree reports an
installation error without replacing an existing usable view. No auto-download.
Verified NERDTree API: 690d061b591525890f1471c6675bcb5bdc8cdff9.
The adapter uses real nodes, UI renderer and FlagSet with instance-local virtual
paths and row lookup; it does not change global NERDTree options or prototypes.
Other upstream revisions remain unverified. See README.md for a pinned checkout
and NERDTREE_RUNTIME setup for developer checks.

                                                       *:DiffviewOpen*
:DiffviewOpen
    Open one dedicated tab with a NERDTree and two read-only diff panes.
    Locate Git from the current working directory, including subdirectories.
    Do not change cwd. Bare repositories are unsupported. There is at most
    one active view; another valid open replaces it.

    Section     Left                         Right
    Staged      HEAD (EMPTY if unborn)        INDEX
    Unstaged    INDEX                         WORKTREE (disk)
    Untracked   EMPTY                         WORKTREE (disk)

    A path with both staged/unstaged edits has two entries. Ignored files
    are excluded. The first file is selected and the panel receives focus.
    Source/path labels are in each content pane's status line. The tree shows
    only changed paths and parent directories, with all directories expanded
    initially. Native flags identify file changes and descendant statuses.
    Deleted/historical paths require no filesystem placeholders. Duplicate
    staged/unstaged paths and file/directory replacements stay separate nodes.
    Renames show the old path beside the new filename. Escaped labels never
    supply the raw path used for selection.

    All displayed buffers belong to the plugin and are read-only. Disk
    snapshots exclude unsaved Vim buffer contents. Browsing never saves,
    reloads, discards or wipes user buffers, or writes to the Git index.
    Files/index are read at selection time; a concurrently changing repo
    is not observed atomically. Historical HEAD blobs stay fixed until
    refresh. Paths are parsed from NUL-delimited records, with control
    characters escaped for display.

:DiffviewOpen {left} {right}
    Directly compare two Git trees, with left/right snapshots in that order.
    Accept revisions resolving to trees, including tree IDs and rev:directory.
    There is no implicit merge-base, revision exclusion (^rev), or .. / ...
    range syntax. Revisions must resolve to one object. Local index,
    disk and unsaved buffer changes do not enter this comparison.

    Exactly zero or two arguments are accepted. Use Vim's backslash escaping
    for whitespace, for example: >
        DiffviewOpen main topic
        DiffviewOpen main:src\ dir topic:src\ dir
<
    Labels show the supplied revisions and resolved short tree object IDs.
    File entries are grouped under Trees. Ref changes remain invisible until
    explicit refresh, which resolves the original arguments again.

                                                       *:DiffviewCommit*
:DiffviewCommit
    Search commits reachable from the current repository's HEAD, including
    merged history, using core fzf. Rows show a short commit ID, date, author
    and subject. Type to search; Enter selects one commit. Esc or Ctrl-C cancels.
    No match/cancel/errors retain the old comparison and unsaved user buffers.

    Requires the optional core junegunn/fzf Vim integration to be loaded and an
    fzf executable on PATH. The separate fzf.vim plugin is not required.
    Install both yourself; Diffview never downloads dependencies. With vim-plug,
    add Plug 'junegunn/fzf' and install the binary through your package manager.
    Core revision b412a45 and binary 0.67.0 were verified; other versions remain
    unverified. The normal core fzf layout preferences are respected.

    Selection opens first-parent-to-commit as below. The full selected ID and
    original repository stay fixed; refresh never reopens the picker. Metadata
    controls are escaped for display and are never interpreted as commands.
    History loading is synchronous and can pause Vim for large repositories.
    Other branches' unique commits, reflogs and file-specific history are not
    searched. Bare/unborn/non-Git repositories report an error.

:DiffviewCommit {revision}
    Directly show changes introduced by one commit, without requiring fzf.
    Use DiffviewCommit HEAD for the former no-argument behavior. The first
    parent is on the left and the commit on the right. Merge commits always
    use their first parent; no combined or three-way diff. Root commits compare
    EMPTY to the commit, without writing a Git object. Missing parent objects
    in shallow/incomplete history cause a Git error, not a false root view.

    Accept exactly one argument resolving to a commit. Labels identify the
    revision and resolved short commit IDs; entries are grouped under Commit.
    Refresh resolves an explicit named revision again, while picked IDs remain
    immutable. Other Diffview commands do not depend on fzf.

                                                       *:DiffviewRefresh*
:DiffviewRefresh
    Explicitly re-read the original repository, regardless of later cwd
    changes. Retain selected section/path when it still exists. There is
    no automatic refresh. Surviving directory expansion state is retained.
    Git/read/NERDTree renderer errors retain the previous comparison.

                                                       *:DiffviewClose*
:DiffviewClose
    Close plugin windows and wipe plugin-owned buffers, returning to the
    originating window when available. Safe to repeat. Manual pane/tab
    closure also cleans up. User-added windows and user buffers survive;
    a custom layout is not reconstructed. A new open validates and prepares
    its content/layout before replacing the previous usable view.

                                                       *diffview-keys*
    Tree:       j/k navigate; <CR> or o selects a file or toggles a directory;
                p selects parent; O recursively expands; X closes descendant
                directories; x closes directory (or selected file's parent).
                Selection retains tree focus.
    All panes:  ]f/[f next/previous file (wrap, revealing ancestors);
                <Tab>/<S-Tab> cycle panes;
                r refresh; q close.
    Diff panes: ]c/[c use Vim's standard diff hunk navigation.
    All plugin mappings are buffer-local. Sections are virtual directories.
    Filesystem mutation, ordinary file-opening, bookmarks and root/cwd-changing
    NERDTree mappings are not installed. Other NERDTree instances are untouched.
    Directory navigation and rendering run no per-node Git commands.
    nerdtree-git-plugin is optional; flags use the comparison model rather than
    its local status cache, so all three comparison modes remain accurate.
    Narrow panes can clip notices and source/path labels. Use Vim's window
    resizing commands to widen the focused pane.

                                                       *ToggleDiffView()*
:call ToggleDiffView()
    Open the local browser, or close any active plugin view.
    g:ToggleDiffView() is the same global function.

                                                       *:DiffBranch*
                                                       *DiffBranch()*
:DiffBranch {branch}
:call DiffBranch('branch')
    Compatibility wrappers for DiffviewOpen {branch} HEAD. g:DiffBranch() is
    the same global function. This intentionally changes the old behavior
    from ref-to-working-tree to committed-tree comparison. Use DiffviewOpen
    without arguments to review local staged/unstaged/untracked changes.

    Upstream argument conventions are not interchangeable: Diffview.nvim and
    CodeDiff commonly compare one revision with the working tree. Here use
    DiffviewCommit rev for parent-to-commit and DiffviewOpen A B for two trees.

                                                       *diffview-limits*
    Clean/unborn empty repositories show No changes and remain refreshable.
    Missing added/deleted sides are empty. Empty existing files are valid;
    missing-final-newline information is retained in 'endofline'. Rename
    rows show old -> new; mode-only entries remain visible.

    Binary files, symlinks, submodules and unmerged index entries show an
    explicit explanation instead of a text diff. Binary detection includes
    Git's binary markers and -diff attributes, even without NUL bytes.
    Symlinks are not followed.
    This includes paths through symlinked directories below the repository root;
    directory components are checked again when selecting a snapshot.
    A file disappearing unexpectedly is a read error, not an empty file.
    Errors are prefixed [diffview]; non-Git/bare cwd creates no partial view.

    Git runs synchronously and large inputs can block Vim. Other versions,
    platforms and unusually large workloads remain unverified.
    Windows support, Git mutations (stage/restore/checkout), history browsing,
    editable panes, automatic refresh and three-way merges are not provided.

    Inspired by https://github.com/sindrets/diffview.nvim navigation/layout;
    uses native Vim9/Git, with no Neovim or Lua dependency.
